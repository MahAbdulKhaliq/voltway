## Phase 1 — Data layer (before any UI)
**Repo layout** (follows phase1-stack.md §2):
```
schema/            JSON Schemas: sourced-value, source, make, model, variant (incl. trims), curve, crosswalk row
sources/           raw downloads, committed: nrcan/, openev/, chargeprice/  (+ fetch date)
data/sources/      the sources table (one JSON per source)
data/imported/     normalized per-source records written by importers (regenerable, reviewable diffs)
data/makes|models|variants|curves/   our hand-entered records; IDs make/model/year/variant
crosswalk/crosswalk.csv   our_variant_id, source, source_key, match_method, confirmed
scripts/           TypeScript: fetch-*, import-*, match, build-data, validate, calibrate
public/data/       build output: index.json (browse/search) + cars/<id>.json (detail)
```
1.1 **Schemas** modeled on OpenEV Data 1.4.x: sourced value = `{value | "unknown", unit, kind, source_id, notes?}` with kinds `rated_nrcan, rated_epa, rated_wltp, manufacturer, tested, community, estimated`; enums for four-state heat pump, chemistry incl. unknown, ports, voltage class; curves ≥2 points sorted by SoC, exactly one display default per variant (checked in validate script). Source URLs required; homepage-only URLs get a `low_confidence` flag. *Done when:* fixture tests prove a bare number, missing source, one-point curve, wrong unit each fail validation.
1.2 **Fetch + NRCan importer:** download BEV CSV (bilingual headers handled), normalize to `data/imported/nrcan/` with kWh/100 km × 10 → Wh/km, range km, 240V recharge h, all `rated_nrcan` with the NRCan source record (OGL-Canada attribution).
1.3 **OpenEV Data importer:** from a pinned release; maps battery gross/usable, chemistry, voltage class, DC/AC kW, ports, heat pump, wheels, EPA/WLTP range, curves if any; values tagged manufacturer-via-OpenEV per the precedence decision.
1.4 **Chargeprice importer** (KilowattApp archive, pinned commit): measured curves → `tested` with source note "Fastned → Chargeprice"; default-curve entries skipped and logged; MIT attribution recorded.
1.5 **Match suggester:** make + year → name similarity → battery kWh + drivetrain tie-breaks; writes suggestions with `confirmed=false` and an unmatched report. **You confirm each row** (I'll present them as a short table). NRCan is the reference list.
1.6 **Starter set:** I propose ~25 popular Canadian EVs from NRCan 2024–2026 for your approval, then hand-enter gaps (Kia etc., ports, heat pump, wheels, published 10–80% times) from Canadian OEM pages, each with a specific-URL source record.
1.7 **Data build:** join via confirmed crosswalk → apply precedence (default value + "other figures") → 5% conflict flags → generate estimated curves from the §9 templates → export index + per-car files. *Done when:* `npm run build` produces files where every figure has kind + source, and a test fails the build on an unsourced value.

## Phase 2 — Charging maths + calibration
2.1 `src/lib/charging.ts` (pure, shared by pages and islands): 0.5% steps, linear interpolation, delivered = min(car, charger), total/ideal/lost time, energy added to battery, avg kW, km added, **km per 10 min**; no loss factor (C9). Vitest with hand-calculated cases (flat curve, charger cap, 0/100 edges).
2.2 `scripts/calibrate.ts`: template 10–80% vs tested curves / published times (tested weighted more), report % error; tune toward ±15%; **I bring you the results and proposed template numbers to approve** before recording them in charging-curve-viewer.md §9.
